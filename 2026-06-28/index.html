読むAgentic Auto-Scheduling: LLM-Guided Loop Optimization (arXiv:2511.00592)

arxiv.org

TL;DR 汎用LLMにコンパイラの実測フィードバックを返す対話ループ『ComPilot』で、ファインチューニング無しにループ最適化を自動化。未最適化比で平均2.66倍（best-of-5で3.54倍）、専用最適化器Pluto比でも2.94倍を達成した実証研究。

  • 仕組み: LLMが最適化案を`<schedule>`で提案→コンパイラ(Tiramisu)が多面体解析で合法性を検証し実測高速比を返す→対話履歴を積んでLLMが反復改善。扱う変換は9種(融合/交換/2D・3Dタイリング/並列化/展開/スキュー等)。
  • 強み: 形式的な合法性チェックを挟むので、LLMが直接コードを書く方式と違い“意味を壊さない”。
  • 実験: 主LLMは gemini-2.0-flash。PolyBench 30カーネル×5サイズ=150件、各40回・1回30反復、best-of-5で評価。
  • 結果の数字: 幾何平均2.66倍(単発)/3.54倍(best-of-5)。correlation_XLARGEで339倍の例も。vs Plutoは119勝9分22敗（小サイズ圧勝・XLARGEは劣勢）。
  • 弱点: LLMの提案の約2/3が無効/違法で探索が非効率。1件平均8.9分かかり、コストの78%はLLMでなくコンパイラ処理側。

→ 使いどころ 『LLMの発想 × コンパイラの正しさ』を実測ループで回すと、微調整なしでも専用最適化器に勝てる領域がある——という有望な実証。ただし提案の質と所要時間がまだ実用の壁。PACT 2025採択。

読むA harness for every task: dynamic workflows in Claude Code

x.com（元記事: claude.com/blog）

TL;DR Claude Code の『dynamic workflows』公式解説。Claude がタスク専用の harness(実行の足場) を JavaScript でその場で書き、多数のサブエージェントをバックグラウンドで編成する機能（2026-06-02 公開）。

  • 解決する3つの失敗モード: agentic laziness(複雑タスクで途中で手を抜く)、self-preferential bias(自分の出力を過信し検証が甘くなる)、goal drift(ターンを重ねて要件を見失う)。
  • harness=エージェントの『計画/分割/検証/実行』を司る足場。既定はコーディング向けだが、Opus 4.8 の能力で“個別タスク用に自動生成”できるようになった点が新しい。
  • 仕組み: JSスクリプトでサブエージェントを spawn/編成。各々独立コンテキスト、worktreeで隔離、モデルを動的選択、中断後 resume も可能。
  • 事例: Bun の Zig→Rust 全面移植、/deep-research スキル、セキュリティレビュー、履歴書80件ランキング等。`use a workflow`/`ultracode` で起動、`~/.claude/workflows` に保存・Skill化。
  • 注意: 単一プロンプトよりトークン消費が大きく、通常タスクには過剰。ベストプラクティスは発展途上。
  • ※ ツイート本文はリンクのみだったため、Anthropic公式ブログ(claude.com/blog)から本文を取得して深掘り。

→ 使いどころ “1つのプロンプト”でなく“タスク専用の multi-agent harness を Claude に書かせる”段階へ。大規模移行・横断調査・大量分類など高価値タスク向け。
